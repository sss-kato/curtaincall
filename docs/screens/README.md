# 画面定義書 目次

要件 `docs/requirements.md` §4.1・§8 を根拠に、app の画面ごとに「何が見え・何ができ・どう遷移するか」を定義する。
実現方法（UseCase・Provider・DB）は書かない。app 設計書（`docs/design/D-xx.md`、scope: app）が本書の ID を参照する。

雛形は `_template.md`。運用は `docs/workflow.md` §3 と `/screen-doc` を参照。

## 機能 ID の割り当て根拠

| 要件 | 置き場所 | 理由 |
|---|---|---|
| F-02 記事項目の表示 | S-00 | 記事セルはホームと保存の両方で使う共通部品 |
| F-05 既読管理 | S-00 / S-01 / S-03 | グレーアウト表示は S-00、未読フィルタは S-01、一括クリアは S-03 |
| F-06 保存 | S-00 / S-02 | スターを付ける操作は記事セル上で行うため S-00。保存一覧は S-02 |
| F-07 プッシュ通知 | S-01 | 通知の画面は作らず、通知タップからの遷移先の状態として S-01 §5 に書く |
| F-11 更新記事の再浮上 | S-00 / S-01 | 「更新」バッジは S-00 のセル、先頭への再表示は S-01 の並び順 |
| アプリ内ブラウザ（§8） | 作らない | iOS 標準（SFSafariViewController）のため実装不要 |
| アプリ情報（§8 設定） | S-03 | 機能 ID は無いが要件 §8 に明記されているため S-03 に含める |

## 執筆順序

```
S-00 → S-01 → S-02 → S-03
```

S-01〜S-03 はすべて S-00 に依存する。S-00 を `approved` にしてから次に進む。

## ID の体系

| ID | 意味 | 例 |
|---|---|---|
| `S-xx` | 画面 | S-01 ホーム |
| `E-nn` | 要素 | E-03 記事セル |
| `ST-nn` | 状態 | ST-04 オフライン |
| `A-nn` | 操作 | A-02 下に引っ張る |

他画面から参照するときは `S-00/E-03` の形で書く。承認後に ID を振り直さない（廃止は行を残す）。
