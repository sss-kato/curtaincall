## 1. 目的

ホーム（S-01）・保存（S-02）・設定（S-03）の 3 画面で共通して使う部品と表示ルールを 1 か所に定める。本書は単独の画面ではなく、各画面定義書から `S-00/E-nn` の形で参照される。ユーザーはどの画面でも同じ見た目の下部タブバーで画面を移動し、同じ形の記事セルで記事を識別し、同じ形の状態表示（読み込み中・空・オフライン・エラー）で状況を把握できる。

本書が定めるのは次の 4 つ。

1. 下部タブバー（要件 §8）
2. 記事セル（F-02・F-05・F-06・F-11）
3. 共通状態表示（各画面の §5 が参照する）
4. 団体名とカテゴリアイコンの表示対応表（要件 §3.1・§3.3・§7）

本書が定めないもの（各画面の担当）：上部の団体タブと横スワイプ（S-01）、未読フィルタ（S-01）、一覧の並び順と更新記事の先頭再表示（S-01）、Pull to Refresh（S-01）、保存記事の一覧（S-02）、既読の一括クリア（S-03）、ブラウザの選択（S-03）。

```

│ E-01 下部タブバー             │
│  E-02 ホーム  E-03 保存  E-04 設定 │
└──────────────────────────────┘

- 画面の最下部に固定。iOS 標準のタブバーの高さ・セーフエリアに従う
- 各タブはアイコン＋ラベルの縦並び。選択中のタブはアイコンとラベルがアクセント色、非選択はセカンダリ色（ST-20）

│ E-10 記事セル                                 │

```

- 左にテキスト領域、右に正方形のサムネイル領域（参考イメージ：SmartNews の一覧セル）。サムネイル領域の 1 辺は 84pt（縦 84pt × 横 84pt。§8 #34）
- 1 行目：E-11 団体名 → E-12 カテゴリアイコン → E-16 更新バッジ（更新時のみ）の順に横並び。1 行に固定し、折り返さない（収まらないときは §7.5「位置」）

- E-17 スターを除くセル全体がタップ領域（A-10）

## 5. 状態

部品ごとに分けて書く。「初期表示」は各画面の §5 が定義するため、本書では記事セルの通常状態 ST-01 と状態表示の非表示をもって初期とする。

### 5.1 記事セル E-10

| ID | 状態 | 発生条件 | 表示 |
|---|---|---|---|
| ST-01 | 未読 | 記事をまだ開いていない | E-11・E-13・E-14 は標準の文字色（ラベル色）。E-13 は太字。E-15 は不透明度 100% |
| ST-02 | 既読 | 記事を開いたことがある（A-10 の後）。設定の一括クリア（S-03）で ST-01 に戻る（`Article.updatedAt` があっても ST-03 にはならない。§7.5） | E-11・E-13・E-14 をセカンダリ文字色に変える。E-13 は標準の太さ。E-15 は不透明度 50%。E-12・E-17 は変えない |
| ST-03 | 更新あり | すでに端末にある記事の更新を検知し、かつ検知の後にその記事を開いていない（§7.5）。端末に初めて入った記事（新着）は `Article.updatedAt` があってもこの状態にならない（§8 #27）。ただし一括クリア（S-03）より前に検知した更新は対象外 | E-16「更新」バッジを表示。文字色・太字は ST-01 と同じ（更新後は未読として扱う。§8 #19） |
| ST-04 | 保存済み | E-17 で保存した（A-11）。保存を解除すると ST-01 / ST-02 の表示に戻る | E-17 が塗りつぶした星になる。他の要素は変えない。ST-02 と同時に成立する |
| ST-05 | サムネイル無し | `Article.thumbnail` が無い | E-15 の領域に画像の代わりに無地のプレースホルダー（背景より一段濃いグレーの角丸四角）を表示し、セルの高さと見出しの幅は ST-01 と同じに保つ（§8 #18） |
| ST-06 | サムネイル未取得 | `Article.thumbnail` はあるが、画像をまだ取得できていない（読み込み中・オフライン・取得失敗）。`Article.thumbnail` が `http` / `https` 以外の URL でそもそも取得できないときもこの状態になる（§8 #32） | ST-05 と同じプレースホルダーを表示。取得できた時点で画像に置き換わる。失敗しても再試行の操作は出さない |

### 5.2 共通状態表示

「取得済みの記事」とは、配置画面のフィルタ・団体タブ（S-01）や保存の有無（S-02）で絞り込む前の、端末に保持している記事全体を指す。取得済みの記事はあるが絞り込みで表示対象が 0 件になった場合は ST-12（空）であり、ST-10・ST-14・ST-16 にはならない（§8 #24）。取得済みの記事が何件あるかを読み出せず、記事の有無そのものが分からない場合は ST-17 であり、ST-12 にはならない（§8 #36）。

| ST-11 | 更新中（記事あり） | 取得済みの記事が 1 件以上ある状態で取得を実行中（起動時の裏での取得、Pull to Refresh） | E-21 を一覧の先頭に表示。記事セルはそのまま操作できる（A-10・A-11 は有効）。この間に下部タブを切り替えても取得は続き、戻ったときに成功の結果（記事の追加・更新）が反映されている。失敗した場合は ST-13 / ST-15 のとおり（ST-13 の帯 E-23 は配置画面に戻ったときに表示されている。ST-15 の E-25 は他のタブを表示中に失敗すると出ない）。表示対象が 0 件（ST-12）のときは E-22 の上に E-21 を出す |
| ST-12 | 空 | 端末に保持している記事を読み出せたうえで、表示対象が 0 件だった（記事が本当に 0 件であることが分かっている。読み出せなかったときは ST-17）。取得済みの記事が 1 件も無い場合は、取得が成功して 0 件だったとき、ST-17 からの再試行（A-12）で端末に保持している記事の読み出しに成功して 0 件だったとき、または配置画面が取得を伴わないとき（S-02）。取得済みの記事がある場合は、フィルタ・団体タブ・保存の有無で 0 件になったとき。取得の実行中・オフライン・エラーの区別は ST-11 / ST-13 / ST-15 の重ね表示で示す。取得済みの記事が 1 件も無い状態での取得中は ST-10 | E-22 を中央に表示。文言は配置画面が指定 |

`Article.publishedAt`（ISO8601）を端末のタイムゾーンに変換して表示する。**時刻は表示しない**（§8 #15）。

| 昨日 | 「昨日」 | 昨日 |

| 前年以前 | `yyyy/M/d` | 2025/12/24 |
| 今日より後（サイト側の日付誤りで未来の日付になっている場合） | 同じ年は `M/d`、翌年以降は `yyyy/M/d`（「今日」「昨日」に当てはまらないため上の 2 行をそのまま適用する。§8 #29） | 9/30、2027/1/5 |

- `Article.fetchedAt` は表示しない

## 8. 決定事項と根拠

| # | 決定 | 採らなかった案 | 理由 |
|---|---|---|---|
| 1 | 記事セルは「左テキスト・右正方形サムネイル」の 1 種類だけにする | サムネイルの有無や団体で複数のセル形を持つ | 要件 §1.3 の参考イメージ SmartNews の一覧セルと同じ形。ホームと保存で同じセルを使えば、既読・保存・更新バッジの見た目が画面間でずれない |
| 2 | 既読になる操作は「記事を開く」だけにする | 一覧でセルが画面に表示されたら既読にする | F-05 の「既読」は読んだ記事を指す。表示だけで既読にすると、見逃した記事が未読フィルタ（S-01）から消えて F-05 の目的に反する |
| 3 | グレーアウトは文字色をセカンダリ色に、サムネイルを不透明度 50% にする。背景色は変えない | セル背景をグレーにする | iOS の標準リスト（メール・メッセージ）は既読を文字の太さと色で示し、背景色は選択状態の表現に使う。背景を変えると選択中と見分けにくい |
| 4 | 全面の読み込み中表示（E-20）は取得済みの記事が 1 件も無いときだけ出し、取得済みの記事があるときは一覧上部のインジケータ（E-21）に留める。ただし起動直後、表示対象が未確定の間（絞り込みの条件である未読フィルタの ON/OFF を端末から読み出している間）は、取得済みの記事があっても E-20 を出す（§5.2 ST-10） | 更新のたびに全面インジケータを出す／表示対象が未確定の間は空表示（E-22）を出す | 要件 §5 起動速度「ローカル DB から即座に一覧表示。ネットワーク取得は裏で実行」。全面表示にすると取得済みの記事が見えなくなる。表示対象が未確定の間に E-22 を出すと、記事があるのに「記事がありません」が一瞬見えて誤りになる（設計レビューで挙がった論点。開発者決定 2026-09-24） |
| 5 | オフライン・エラーで取得済みの記事があるときは、記事を表示したまま帯（E-23）または一時表示（E-25）で知らせる | ダイアログで知らせる | 要件 §5 オフライン時「取得済みの記事は閲覧可能」。ダイアログは閲覧を妨げる。iOS の標準的なアプリ（App Store・ニュース）もオフラインは非モーダルで示す |
| 6 | エラー（記事あり）E-25 に「再試行」ボタンを置かない | E-25 に再試行ボタンを置く | ホームには Pull to Refresh（F-10・S-01）があり、再試行の手段が重複する。取得の失敗による E-25（ST-15）は、取得を伴わない保存画面（S-02）では出ない。記事を開けなかったときの E-25 は S-02 にも出るが、これは再試行で結果が変わらない知らせのためボタンを置かない（#37） |
| 7 | 記事セルに長押しメニュー・スワイプ操作を付けない | 長押しで共有メニュー、スワイプで保存・既読切替 | 共有（F-55）は要件 §4.2 で MVP 外。保存はスター E-17 で完結し、既読は開けば付くため、隠れた操作を増やす必要がない |
