## 1. 目的

ホーム（S-01）・保存（S-02）・設定（S-03）の 3 画面で共通して使う部品と表示ルールを 1 か所に定める。本書は単独の画面ではなく、各画面定義書から `S-00/E-nn` の形で参照される。ユーザーはどの画面でも同じ見た目の下部タブバーで画面を移動し、同じ形の記事セルで記事を識別し、同じ形の状態表示（読み込み中・空・オフライン・エラー）で状況を把握できる。

本書が定めるのは次の 4 つ。

1. 下部タブバー（要件 §8）
2. 記事セル（F-02・F-05・F-06・F-11）
3. 共通状態表示（各画面の §5 が参照する）
4. 団体名とカテゴリアイコンの表示対応表（要件 §3.1・§3.3・§7）

本書が定めないもの（各画面の担当）：上部の団体タブと横スワイプ（S-01）、未読フィルタ（S-01）、一覧の並び順と更新記事の先頭再表示（S-01）、Pull to Refresh（S-01）、保存記事の一覧（S-02）、既読の一括クリア（S-03）、ブラウザの選択（S-03）。

## 5. 状態

部品ごとに分けて書く。「初期表示」は各画面の §5 が定義するため、本書では記事セルの通常状態 ST-01 と状態表示の非表示をもって初期とする。

### 5.1 記事セル E-10

| ID | 状態 | 発生条件 | 表示 |
|---|---|---|---|
| ST-01 | 未読 | 記事をまだ開いていない | E-11・E-13・E-14 は標準の文字色（ラベル色）。E-13 は太字。E-15 は不透明度 100% |
| ST-02 | 既読 | 記事を開いたことがある（A-10 の後）。設定の一括クリア（S-03）で ST-01 に戻る | E-11・E-13・E-14 をセカンダリ文字色に変える。E-13 は標準の太さ。E-15 は不透明度 50%。E-12・E-17 は変えない |
| ST-03 | 更新あり | `Article.updatedAt` が存在し、かつその更新の後に記事を開いていない（§7.5） | E-16「更新」バッジを表示。文字色・太字は ST-01 と同じ（更新後は未読として扱う。§8 #19） |
| ST-04 | 保存済み | E-17 で保存した（A-11）。保存を解除すると ST-01 / ST-02 の表示に戻る | E-17 が塗りつぶした星になる。他の要素は変えない。ST-02 と同時に成立する |
| ST-05 | サムネイル無し | `Article.thumbnail` が無い | E-15 の領域に画像の代わりに無地のプレースホルダー（背景より一段濃いグレーの角丸四角）を表示し、セルの高さと見出しの幅は ST-01 と同じに保つ（§8 #18） |
| ST-06 | サムネイル未取得 | `Article.thumbnail` はあるが、画像をまだ取得できていない（読み込み中・オフライン・取得失敗） | ST-05 と同じプレースホルダーを表示。取得できた時点で画像に置き換わる。失敗しても再試行の操作は出さない |

## 7. 表示ルール

### 7.1 団体の表示対応（`Article.companyId` → 表示名）

要件 §3.1 の 5 団体。表示名は団体定義（companies.json、要件 §3.1）から取得する。本書は「どの文字列を出すか」を決める。

| `companyId` | 記事セル E-11 の表示名（§8 #16） | 正式名（要件 §3.1） |
|---|---|---|
| `takarazuka` | 宝塚 | 宝塚歌劇団 |
| `shiki` | 四季 | 劇団四季 |
| `horipro` | ホリプロ | ホリプロステージ |
| `toho` | 東宝 | 東宝（演劇） |
| `shinkansen` | 新感線 | 劇団☆新感線 |

- E-11 の表示名は F-01 の上部タブ名（宝塚／四季／ホリプロ／東宝／新感線）と同じ文字列を使う
- 対応表に無い `companyId` の記事（団体定義の追加が先行した場合）は、E-11 に `companyId` の文字列をそのまま表示する（記事を隠さない）

### 7.2 カテゴリの表示対応（`Article.category` → アイコンとラベル）

要件 §7 の 7 値。アイコンは単色のシンボル（E-11 と同じ高さ）で、モードに応じてセカンダリ色で描画する。ラベルは画面には出さず、VoiceOver の読み上げに使う。

| `category` | 要件 §3.3 の名称 | ラベル（読み上げ） | アイコンのモチーフ（§8 #17） |
|---|---|---|---|
| `new_work` | 新作発表 | 新作発表 | きらめき（スパークル） |
| `ticket` | チケット情報 | チケット情報 | チケット |
| `streaming` | 配信・映像化 | 配信・映像化 | 再生（▶） |
| `schedule` | 公演スケジュール | 公演スケジュール | カレンダー |
| `cast` | キャスト情報 | キャスト情報 | 人物 2 人 |
| `person` | 出演者ニュース | 出演者ニュース | 人物 1 人 |
| `other` | （その他） | お知らせ | 情報（i） |

- 対応表に無い `category` は `other` と同じ表示にする

### 7.3 日時（E-14）

`Article.publishedAt`（ISO8601）を端末のタイムゾーンに変換して表示する。**時刻は表示しない**（§8 #15）。

| 条件 | 書式 | 例（今日が 2026/9/13 のとき） |
|---|---|---|
| 今日 | 「今日」 | 今日 |
| 昨日 | 「昨日」 | 昨日 |
| 一昨日以前で同じ年 | `M/d` | 9/1、8/28 |
| 前年以前 | `yyyy/M/d` | 2025/12/24 |

- 「今日」「昨日」の判定は端末の日付による（日付が変わった時点で表示も変わる）
- `Article.updatedAt` は E-14 に表示しない（更新は E-16 バッジで示す。§7.5）
- `Article.fetchedAt` は表示しない

### 7.4 既読（F-05）

| 対象 | ルール |
|---|---|
| 既読になる操作 | A-10（記事を開く）のみ。スクロールで表示されただけでは既読にならない |
| グレーアウトの対象 | E-11・E-13・E-14 の文字色をセカンダリ文字色に、E-13 を太字から標準の太さに、E-15 の不透明度を 50% に |
| 変えないもの | E-12 カテゴリアイコン、E-17 スター、セル背景色 |
| 反映のタイミング | 記事を開いて一覧に戻った時点で反映されている |
| 未読に戻る条件 | 設定の一括クリア（S-03）。更新記事の扱いは §7.5 |

### 7.5 更新バッジ（F-11）

| 対象 | ルール |
|---|---|
| 表示条件 | `Article.updatedAt` が存在し、かつ更新後に記事を開いていない（ST-03） |
| 消える条件 | 記事を開いた（A-10）時点で消える。時間経過では消えない（§8 #19） |
| 既読との関係 | 更新を検知した記事は、それ以前に開いていても未読（ST-01 相当の見た目）に戻り、バッジ付きで表示する（§8 #19） |
| 文言 | 「更新」の 2 文字。固定 |
| 位置 | E-12 カテゴリアイコンの右。1 行目に収まらない場合も改行せず、E-13 見出しの幅を優先する |

### 7.6 サムネイル（E-15）

| 対象 | ルール |
|---|---|
| 取得元 | `Article.thumbnail` の URL を直接参照する。端末にコピー保存しない（調査レポート §6.2、CLAUDE.md）。オフライン時に未取得の画像は ST-06 のプレースホルダーになる |
| 領域 | セル右端の正方形。縦横 1:1。画像の縦横比が異なる場合は中央を基準にトリミングして領域を埋める |
| 角 | 角丸（小） |
| 無いとき | ST-05（無地のプレースホルダーで領域を保つ。§8 #18） |
| 既読時 | 不透明度 50%（§7.4） |

### 7.7 見出し（E-13）

| 対象 | ルール |
|---|---|
| 行数 | 最大 3 行 |
| 省略 | 3 行を超える部分は末尾を「…」で省略。先頭・中間の省略はしない |
| 太さ | 未読は太字、既読は標準（§7.4） |
| 文字サイズ | iOS の本文サイズ（Dynamic Type に追従。拡大時も 3 行で省略） |
| 空文字 | `Article.title` が空のときは「（見出しなし）」を表示する |

### 7.8 ダークモード（F-09）

| 対象 | ルール |
|---|---|
| 追従 | 端末のシステム設定に自動追従。アプリ内の切替は置かない |
| 色 | 文字・背景・区切り線・タブバー・帯・バッジはすべて iOS のシステム色（ラベル色・セカンダリラベル色・システム背景色・アクセント色）を使い、モードごとの個別指定を持たない |
| サムネイル | モードによる加工はしない |
| 例外 | なし |

### 7.9 並び順

本書では決めない。ホームは S-01 §7、保存は S-02 §7 が定める。

## 8. 決定事項と根拠

| # | 決定 | 採らなかった案 | 理由 |
|---|---|---|---|
| 1 | 記事セルは「左テキスト・右正方形サムネイル」の 1 種類だけにする | サムネイルの有無や団体で複数のセル形を持つ | 要件 §1.3 の参考イメージ SmartNews の一覧セルと同じ形。ホームと保存で同じセルを使えば、既読・保存・更新バッジの見た目が画面間でずれない |
| 2 | 既読になる操作は「記事を開く」だけにする | 一覧でセルが画面に表示されたら既読にする | F-05 の「既読」は読んだ記事を指す。表示だけで既読にすると、見逃した記事が未読フィルタ（S-01）から消えて F-05 の目的に反する |
| 3 | グレーアウトは文字色をセカンダリ色に、サムネイルを不透明度 50% にする。背景色は変えない | セル背景をグレーにする | iOS の標準リスト（メール・メッセージ）は既読を文字の太さと色で示し、背景色は選択状態の表現に使う。背景を変えると選択中と見分けにくい |
| 4 | 全面の読み込み中表示（E-20）は記事が 0 件のときだけ出し、記事があるときは一覧上部のインジケータ（E-21）に留める | 更新のたびに全面インジケータを出す | 要件 §5 起動速度「ローカル DB から即座に一覧表示。ネットワーク取得は裏で実行」。全面表示にすると取得済みの記事が見えなくなる |
| 5 | オフライン・エラーで記事があるときは、記事を表示したまま帯（E-23）または一時表示（E-25）で知らせる | ダイアログで知らせる | 要件 §5 オフライン時「取得済みの記事は閲覧可能」。ダイアログは閲覧を妨げる。iOS の標準的なアプリ（App Store・ニュース）もオフラインは非モーダルで示す |
| 6 | エラー（記事あり）E-25 に「再試行」ボタンを置かない | E-25 に再試行ボタンを置く | ホームには Pull to Refresh（F-10・S-01）があり、再試行の手段が重複する。保存画面（S-02）は取得を伴わないため E-25 自体が出ない |
| 7 | 記事セルに長押しメニュー・スワイプ操作を付けない | 長押しで共有メニュー、スワイプで保存・既読切替 | 共有（F-55）は要件 §4.2 で MVP 外。保存はスター E-17 で完結し、既読は開けば付くため、隠れた操作を増やす必要がない |
| 8 | 選択中のタブを再タップすると一覧を先頭までスクロールする（A-02） | 何もしない | iOS の標準的なタブバーの振る舞い（App Store・ミュージック等）。設定（E-04）は一覧が短いため対象外 |
| 9 | タブ切替で各画面のスクロール位置と上部タブの選択を保持する | 切り替えるたびに先頭に戻す | iOS のタブバーの標準的な振る舞い。読んでいた位置に戻れないと巡回の手間（要件 §1.2）が増える |
| 10 | ダークモードはシステム追従のみで、アプリ内切替を置かない | 設定画面にライト／ダーク／自動の切替を置く | F-09「端末のシステム設定に自動追従」。要件 §8 の設定画面の項目にも含まれない |
| 11 | 団体名は E-11 に必ず表示し、非表示にする設定を置かない | 団体タブ選択中（S-01）は団体名を省く | 調査レポート §6.2「各記事に団体名を必ず表示し、出典が明確になるようにする」。同じセルをホーム「すべて」と保存でも使うため、常時表示のほうが一貫する |
| 12 | 対応表に無い `companyId` / `category` の記事を隠さず表示する | 未知の値の記事を除外する | 要件 §3.1「団体の定義は設定ファイルで外出しし、アプリ本体の改修なしに増やせる」。アプリ更新前に団体が増えても記事が消えない |
| 13 | `Article.fetchedAt`・`Article.updatedAt`・`Article.url`・`Article.id`・`Article.contentHash` は画面に表示しない | 更新日時を E-14 に併記する | F-02 の表示要素は 5 つ（団体名・カテゴリアイコン・見出し・公開日時・サムネイル）。更新は F-11 の「更新」バッジで示せば足りる |
| 14 | カテゴリはアイコンのみで、テキストラベルを画面に出さない（VoiceOver のみ） | アイコン＋テキスト | F-02 の記述は「カテゴリアイコン」。1 行目に団体名・アイコン・バッジが並ぶため、ラベルを足すと見出しの幅が減る |
| 15 | 公開日時（E-14）は日付のみ（今日 / 昨日 / M/d / yyyy/M/d）で、時刻を表示しない（§7.3） | 相対表記（「3 時間前」「2 日前」）／日付＋時刻（当日は HH:mm） | 調査レポートより、HTML 解析の 3 団体（宝塚・四季・東宝）は掲載日が日付のみで時刻を持たない。時刻や相対表記を使うと 00:00 扱いの記事が混ざり「今日 0:00」「23 時間前」のような誤解を招く。日付のみなら 5 団体で一貫する（開発者回答 2026-09-13、旧 Q-1） |
| 16 | 記事セル E-11 の団体名は短縮名（宝塚 / 四季 / ホリプロ / 東宝 / 新感線）にする（§7.1） | 正式名（宝塚歌劇団 / 劇団四季 / ホリプロステージ / 東宝（演劇） / 劇団☆新感線） | 1 行目に団体名・カテゴリアイコン・更新バッジが並ぶため、短いほうが見出しの幅を確保できる。F-01 の上部タブと同じ文字列なので対応がわかりやすい（開発者回答 2026-09-13、旧 Q-2） |
| 17 | カテゴリアイコン（E-12）のモチーフは §7.2 の表（スパークル / チケット / 再生 / カレンダー / 人物 2 人 / 人物 1 人 / 情報）にする | アイコンを使わずカテゴリ名の短いテキストタグ（「新作」「チケット」…）にする | F-02 が「カテゴリアイコン」と明記。採用したモチーフは iOS の標準シンボルに同等のものがあり、ライト／ダークで単色描画できる。`cast` と `person` の区別が弱い点は VoiceOver ラベル（§7.2）で補う（開発者回答 2026-09-13、旧 Q-3） |
| 18 | サムネイル無し（ST-05）は無地のプレースホルダーで領域を保つ（§7.6） | サムネイル領域を詰めて見出しを全幅にする／カテゴリアイコンを大きく置いたプレースホルダー | セルの高さと見出しの幅が一定になり、一覧のスクロールが安定する。未取得（ST-06）と同じ表示にできるため、画像の取得前後でレイアウトが動かない。領域を詰める案は SmartNews に近いが、サムネイルが取れやすい RSS の 2 団体とそれ以外で一覧の見た目が偏る（開発者回答 2026-09-13、旧 Q-4） |
| 19 | 更新バッジ（E-16）は更新後に記事を開いたら消える。更新を検知した記事は既読が解除され未読に戻る（§7.5） | 既読状態を維持してバッジだけ付ける／更新検知から 24 時間で消す | F-11 の目的は「書き換わった記事を見逃さない」こと。未読に戻せば S-01 の未読フィルタ（F-05）でも拾える。既読を維持すると未読フィルタ中に更新記事が見えず、時間経過で消すと開かなくても消えて見逃しが起きる（開発者回答 2026-09-13、旧 Q-5） |
| 20 | スター（E-17）はセル右下に常時表示する（§3.2） | セルを左スワイプして出るアクション／サムネイルの上に重ねる | F-06 の主操作を見える場所に置くほうが、初めて使う身内（要件 §2 フェーズ 2）にも発見しやすい。スワイプは iOS 標準だが隠れる。サムネイル上に重ねる案はサムネイル無し（ST-05）のときに浮く（開発者回答 2026-09-13、旧 Q-6） |
| 21 | 共通文言は §4 のとおり確定する（E-23「オフラインです。最後に取得した記事を表示しています」、E-24「記事を取得できませんでした」／「時間をおいてもう一度お試しください」／「再試行」、E-24 オフライン時「オフラインです」／「インターネットに接続してから再試行してください」、E-25「更新に失敗しました」、E-13 空文字「（見出しなし）」、E-16「更新」） | 別の文言 | 要件に文言の指定が無い。敬体で統一し、原因（オフライン／取得失敗）と今の状態（前回の記事を表示中）をそれぞれ 1 文で示す。S-01 / S-02 の空表示（E-22）の文言は各画面が決める（開発者回答 2026-09-13、旧 Q-7） |
