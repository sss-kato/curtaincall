## 1. 目的

アプリを開いた直後に、対象 5 団体の最新記事が新しい順に一覧で見える画面。上部の団体タブで「すべて」と各団体を横スワイプで切り替え、記事をタップして公式ページを開く。引っ張って最新の記事を取り込み、未読フィルタで未読の記事だけに絞り込める。プッシュ通知をタップしたときの到達先もこの画面である。

本書は S-00（共通部品）に依存する。下部タブバー・記事セル・共通状態表示・日時や団体名の書式は S-00 の ID を参照し、本書では再定義しない。本書が定めるのは、上部の団体タブ、記事一覧の並び順と絞り込み、未読フィルタ、Pull to Refresh、通知タップからの遷移、空表示の文言、および S-01 固有の状態である。

## 3. 画面構成

iPhone・縦向きを前提とする。横向き固有のレイアウトは定義しない（要件 §5）。

```
┌──────────────────────────────────────┐
│ E-01 ナビゲーションバー        E-02 [絞込] │  ← タイトル「CurtainCall」、右端に未読フィルタ（§8 #17）
├──────────────────────────────────────┤
│ E-03 上部団体タブバー                    │
│ E-04     E-05   E-06   E-07     E-08   E-09  │
│ すべて   宝塚   四季   ホリプロ  東宝   新感線 │

├──────────────────────────────────────┤
```

- E-01・E-03 は画面上部に固定され、E-11 をスクロールしても動かない
- E-10 は E-03 のタブと同じ数のページ（E-11）を横に並べたもので、常に 1 ページ分が見える。横スワイプ中（ST-13）だけ隣のページが部分的に見える

- 取得済みの記事が 1 件も無いとき、および端末に保持している記事を読み出せないとき（ST-19）の全面表示（S-00/E-20・E-24）は E-10 の領域全体に出す。E-01・E-03・S-00/E-01 は表示したままにする

## 7. 表示ルール

記事セル内の書式（日時・団体名・カテゴリアイコン・既読・更新バッジ・サムネイル無し・長い見出し・ダークモード）は S-00 §7.1〜7.8 のとおりで、本書では再定義しない。

### 7.1 並び順（F-01・F-11）

| 対象 | ルール |
|---|---|
| 第 1 キー | 「並び順の日時」の降順（新しいものが上）。並び順の日時は `Article.updatedAt` があればその値、無ければ `Article.publishedAt`（§8 #6） |
| 第 2 キー | 並び順の日時が同じときは `Article.fetchedAt` の降順 |
| 第 3 キー | それも同じときは `Article.id` の昇順（表示のたびに順序が入れ替わらないようにする） |
| 既読・保存との関係 | 既読・保存・「更新」バッジの有無で位置は変わらない。記事を開いても位置は動かない |
| 更新記事の再浮上（F-11） | 更新を検知した記事は `Article.updatedAt` が並び順の日時になるため、検知日時の位置（それより新しい記事が無ければ先頭）に移動する。バッジの表示・消去は S-00 §7.5 |
| 日付のみの記事 | HTML 解析の 3 団体（宝塚・四季・東宝）の `Article.publishedAt` は時刻を持たない（調査レポート）。同じ日の記事では、時刻を持つ RSS の記事が日付のみの記事より上に並ぶ。日付のみの記事同士は第 2・第 3 キーで並ぶ |
| タブによる違い | 「すべて」と各団体のページで同じルール。「すべて」は 5 団体の記事を混在させて並べる |

### 7.2 団体タブによる絞り込み（F-01）

| タブ | 表示対象 |
|---|---|
| E-04 すべて | 取得済みの記事全件（団体定義に無い `companyId` の記事も含む） |
| E-05〜E-09 | `Article.companyId` がそのタブの団体に一致する記事だけ |

### 7.3 未読フィルタによる絞り込み（F-05）

| 対象 | ルール |
|---|---|
| OFF（ST-12） | §7.2 の表示対象をすべて表示する |
| ON（ST-11） | §7.2 の表示対象のうち、未読の記事（S-00/ST-01 または S-00/ST-03）だけを表示する。既読（S-00/ST-02）は保存済みでも表示しない |
| 適用範囲 | 全タブ共通。タブを切り替えてもフィルタの ON/OFF は変わらない（§8 #4） |
| 記事を開いた後 | ON のとき、開いた記事は一覧に戻った時点で消える（A-11。§8 #5） |
| 一括クリア（S-03）の後 | すべての記事が未読に戻るため、ON でも全記事が表示される |
| 更新を検知した記事 | S-00 §7.5 のとおり未読に戻るため、ON でも表示される |

### 7.4 取得結果の反映（F-10・F-11）

| 対象 | ルール |
|---|---|
| 新着 | 端末に無かった `Article.id` の記事を §7.1 の位置に差し込む。未読（S-00/ST-01）として表示 |
| 更新 | `Article.updatedAt` が新しくなった記事を §7.1 の位置に移動し、S-00 §7.5 のとおりバッジ付きの未読にする |
| 削除 | §7.5 の上限から外れた記事を一覧から消す |
| 表示位置 | E-11 の先頭を表示中なら、差し込まれた記事が先頭に現れる。先頭以外を表示中なら、表示中の記事の画面上の位置を保つ（新着は上方に入り、スクロールで戻ると見える）。表示中の記事が削除された場合は、その直後の記事を同じ位置に表示する |
| 既読・保存 | 同じ `Article.id` の記事の既読・保存の状態は取得の前後で保たれる |
| 差分なし | 一覧は変わらない。S-00/E-21 が消えるだけ |
| 反映のタイミング | 取得が成功した時点で、表示中のタブにかかわらず全ページに反映する |

## 8. 決定事項と根拠

| # | 決定 | 採らなかった案 | 理由 |
|---|---|---|---|
| 1 | 上部タブはラベルのみのテキストタブで、選択中は下線＋アクセント色。ナビゲーションバーの下に固定し、一覧をスクロールしても隠れない | アイコン付きタブ／セグメントコントロール／スクロールで隠れるタブ | 要件 §1.3 の参考イメージ SmartNews の上部チャンネルタブと同じ形。6 タブを iPhone の幅に収めるにはテキストのみが必要。固定にしないと横スワイプ中に現在のタブが分からない |
| 2 | タブの切り替えはタップ（A-01）と横スワイプ（A-02）の両方。端で折り返さない（「新感線」から右にスワイプしても「すべて」に戻らない） | スワイプのみ／端で循環する | F-01「横スワイプで切替」。タップは離れたタブへ直接移るために必要。循環は iOS のページングの標準にない振る舞いで、端に着いたことが分からなくなる |
