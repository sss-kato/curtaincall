### D-03 追随事項（設計書を reopen するときにまとめて反映）
- §4.1 コード片: `Category` の import 元は `domain/article`
- §4.4: TZ 無しの `pubDate` は `invalid_date`（`NAIVE_TIME_SUFFIX_RE`）。TZ 付きは書式を問わず採用。日付は `pubDate → date(dc:date) → isoDate` の順（`isoDate` は rss-parser がプロセス TZ で作るため最後の予備）
- §4.4 / §4.5: rss-parser の出力は型として信用せず `unknown` + 型ガード（`asText` / `isMediaField`）。`customFields` は `keepArray: true`
- §4.5 / §6 / §7.3: CDATA 内エンティティは rss-parser が展開しない（テストはテキストノードで検証）
- §5.1 手順 6: 複数 URL 構成時の「一部 0 件」の扱い（ホリプロは 1 URL なので現状維持）
- §6: link・サムネイルは http(s) のみ（`javascript:` / `mailto:` / `data:` は `no_link` / サムネイル無し）。破棄ログの url は 200 字
- §7.2 テストダブル一覧に `test/helpers/build-rss.ts` を追加（合成 RSS ビルダ。K2 新感線も使う）
- §7.3 共通契約行: RSS 2 団体の「同一ページ内 url 重複なし」は合成フィードで検証。実データの重複投稿は 2 件とも返す（K2 も同様）
- §7.3 ホリプロ行: 「isoDate 有り」は `dc:date` で実現（rss-parser が `date → isoDate` を派生）
- §7.2 README: 「更新手順（サイト改装時）」節を追加
