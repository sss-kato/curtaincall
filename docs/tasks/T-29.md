### 実装で効いた判断

- **テストは in-memory drift の実物 Repository を使う**（D-05 §7 が明示している方式）。architecture が「CLAUDE.md の『Repository はモックに差し替える』と矛盾しないか」を検証し、**CLAUDE.md の app 節が `test/helpers/` のテストダブルとして「in-memory DB」を明記している**ため、差し替え対象は「端末の実 DB ファイル」であり適合すると判定
- **Stream の検証は `package:async` の `StreamQueue` ではなく `collectStream` + `pumpEventQueue()`**。`NativeDatabase.memory()` は同一 isolate の同期実行なので実時間に依存しない（flutter-expert が n=1 でも届くことを実測。既定 20 に対して 20 倍の余裕）。**発火回数そのものを `hasLength(2)` で検証できる点は `StreamQueue`（「次の値」しか見ない）より強い**
- `HomeArticles.items` を `List.unmodifiable` にし、`==` / `hashCode` とも `package:collection` の `ListEquality` で対称に（application を Flutter 非依存に保つため `foundation.listEquals` は使わない）
