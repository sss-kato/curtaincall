### 設計上の要点（次に触る人へ）

- **保存画面での解除は保留**し、離脱時に `CommitSavedChangesUseCase` が確定する。**ホームでの解除は即時**（`in_feed = true` のため削除対象なし）。`ToggleSavedUseCase` は `deleteUnsavedOutOfFeed` を呼ばない（D-05 §8.1・S-02 §7.3。D-04 §4.2 の旧文面を読むと逆に実装しかねない）
- `execute` は手順 1（解除）→ 2（再保存）→ 3（配信外削除）を**与えられた集合／Map の反復順に 1 件ずつ**処理し、失敗した時点で打ち切る。`committed` に載るのは**手順 1 で成功した id のみ**
- `on Object catch` は意図的。drift は close 済み DB に `StateError`（`Error`）を投げるため、`Exception` に絞ると失敗時に `committed` が呼び出し側へ渡らない（T-40 で確立した事実。テストで固定済み）
- `removeAll(resaveTargets.keys)` は **release 専用の保険**で、debug では直前の `assert` が先に落ちるため自動テストを持たない
