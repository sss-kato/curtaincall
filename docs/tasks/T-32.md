- 異常系 5 件（`javascript:alert(1)`・`file:///etc/passwd`・`/relative`・空文字・`https://`）は **Dart の `Uri` ではすべて `host` が空**になるため、`uri.host.isEmpty` の 1 条件だけで弾かれていた。`host` が非空の非 http スキーム 2 件（`javascript://example.com/%0aalert(1)`・`ftp://example.com/a`）を足してスキーム判定の識別点を作った
- drift の `StateError`（`Error` であって `Exception` ではない）を `on Object` で正しく捕捉していることを、ミューテーション（`on Exception` への変更）で確認

### 対応しなかった指摘

いずれも設計書の変更を伴うため、申し送りとする。

- **URL の `userInfo` を検証していない**（security）。`https://takarazuka.jp@evil.com/x` が検証を通る。`SFSafariViewController` は実ドメインを表示するので詐称の実効性は低く、リポジトリ侵害が前提。**D-05 §5.3 手順 1 の条件を変える**ことになる
- **手順 2 で `browserChoice()` の例外を握り潰した事実がどこにも記録されない**（flutter-expert・adversarial）。`OpenArticleResult` にフィールドを足す必要があり **D-05 §4.1・§5.3 の変更**を伴う
- **`LoggingOpenArticleAction` の bool 写像が自動テストで覆われていない**（adversarial。M11〜M15 が生存）。**CLAUDE.md が「個別クラスのユニットテストは書かない」と定めており規約外**
- **`SettingsRepository`（10 メソッド）のインターフェース分離**（architecture）。**D-05 §4.3 が 1 インターフェースとして確定している**
