## 内容

`fix/publish-staged-diff`（publish 障害のホットフィックス）で `collector/test/infrastructure/storage/git-articles-publisher.test.ts` を追加したが、これは承認済みの設計書と規約が**名指しで対象外にしているクラス**のテストであり、乖離が残っている。

- `docs/design/D-02.md` §7.3：「`main.ts`・`ConsoleLogger`・`SystemClock`・**`GitArticlesPublisher`**・`FirebaseNotificationGateway` の単体テストは書かない。例外として `FetchHttpClient` と `ArticlesFileStore` の 2 クラスは…」
- `CLAUDE.md` テスト方針：例外の対象を「`FetchHttpClient`・`ArticlesFileStore`」の閉じた列挙で書いている

テストを追加した判断自体は spec-reviewer も「妥当」としている。`execFile` を丸ごとスタブ化すれば実 git を一切起動せずに検証でき、§7.3 が除外理由としていた「git を実行するコードはテストで呼ばない」という前提がここでは成立しないため。

問題は**乖離を残したまま確定させること**で、将来の開発者が §7.3 を根拠にこの回帰テストを削除し、同じ盲点（記事が 1 件でも変われば publish が必ず失敗する）が復活しうる。
