## 内容

`GitArticlesPublisher.publish()` は手順 3-3 で `git commit` してから手順 3-4 で `git push` する。push が失敗すると手順 3-6 の復元 `git checkout origin/main -- data/articles.json` が走るが、**これは作業ツリーと index を戻すだけで、手順 3-3 で作ったローカルコミットは残る**。

同じ作業ツリーで次回実行すると、`git add` 後の `git diff --cached --quiet` が 0（HEAD と一致）を返すため、新着があるのに `no_changes` を返して**成功扱いで終わる**。配信が止まったまま障害が隠れる（要件 R-2 の検知を損なう）。

GitHub Actions は毎回クリーンチェックアウトなので現状は自己回復するが、ローカル実行・セルフホストランナーでは成立しない。

**publish のホットフィックス（`isExecFileError` の `null` 未対応の修正）によって commit / push が本番で初めて到達可能になった**ため、これまで顕在化していなかっただけである点に注意。

## 完了条件

- [ ] push 失敗後に同じ作業ツリーで再実行しても、`no_changes` ではなく正しく差分が検出されること
- [ ] 手順 3-6 の復元が、自分が作ったコミットに限定して巻き戻すこと（他人のコミットを巻き戻さない）
- [ ] 対応する回帰テスト（`execFile` をスタブ化。commit 成功 → push 失敗 → 再実行の並び）がある
- [ ] D-02 §5.3 手順 3-6 の記述を追随させる（`/design-doc reopen D-02`。T-37 と同じ reopen にまとめてよい）
- [ ] 品質ゲートを通過している（`npm run lint && npx tsc --noEmit && npx vitest run`）
