## 内容

画面定義書 S-00〜S-03 の approved 化（2026-09-24）に伴い D-04 が改訂され、実装済みコード（T-23・T-24）との差分が生じた。その差分を引き取る。

主な変更は 3 つ。

1. **件数の写像を 4 値にする**：`bool? resolveHasArticles` → `ArticleCountState { pending, unavailable, empty, present }` を返す `resolveArticleCount(count, {required bool retryRequested})`。S-00/ST-17「記事を読み出せない（件数そのものが分からない）」を表すため
2. **判定表を 10 行にする**：先頭行で `unavailable` を拾い、3 行目で件数と一覧の更新順のずれを吸収する
3. **再試行を 2 系統に分ける**：ST-14 / ST-16 は取得をやり直す、ST-17 は端末の読み出しだけをやり直す。`countRetryRequestedProvider.retry()` が `state = true` と `ref.invalidate(articleCountProvider)` を 1 メソッドで行う

`ref.invalidate` は直前値を捨てない（Riverpod の `copyWithPrevious` が両経路で値を引き継ぐ）ため、写像の入力に `retryRequested` を渡して「受動的な失敗では直前値を保つ／明示的な再試行では捨てる」を表す。詳細は D-04 §5.4.1〜§5.4.4。
