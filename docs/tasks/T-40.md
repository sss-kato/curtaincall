## 内容

対応外 `schemaVersion` を検知している間は起動時・復帰時の取得を抑止するが、現在の設計では `SyncCoordinator._start` が `SyncStarted` を流した**後**に `SyncArticlesUseCase` の中で抑止を判定している。そのため `inProgress` が true になり、S-00/E-21（更新中インジケータ）が出てしまう。抑止判定は DB 読みを伴い、`launch` では DB の open と migration を含むため 1 フレームを超えうる。

判定を `SyncSuppressionPolicy` として切り出し、`SyncCoordinator` が `execute` を呼ぶ前に評価する。抑止時は **`SyncStarted` を流さず** `SyncCompleted(trigger, SyncFailed(unsupportedSchema, suppressed: true))` だけを流す。これで「取得そのものを行わなかったときは E-21 も E-25 も出さない」（S-00 §8 #31・S-01 §8 #23）を構造で担保する。

あわせて `_start` の手順 3 (b) で `_disposed` と `isCancelled()` を再確認する。抑止判定の完了前に全体タイムアウトすると、対応する `SyncCompleted` の無い `SyncStarted` が後から流れて `inProgress` が true のまま固まるため。
