## 内容

D-02 §10 **Task E（http ラッパー）の残項目**。「状態」セルは「実装済み。残作業あり：§8.1 (x)（タイムアウトの例外名を `TimeoutError` に直す）と (h) のうち `fetch-http-client.ts` のコメント削除」。

Node 22 の `AbortSignal.timeout` は `DOMException` の `name === "TimeoutError"` を投げ、`"AbortError"` ではない（接続自体の失敗は `TypeError`）。D-02 §5.7 手順 4・§7.2 `stubFetch()`・§7.3 のケースはこの実測に合わせて改訂済みなので、実装側のコメントとテストのスタブを設計書に合わせる。

着手時の実測（2026-10-17）では、`src/infrastructure/http/fetch-http-client.ts:178-179` に「設計書の表記が `"AbortError"` だが…」という D-02 追随コメントが残り、`test/infrastructure/http/fetch-http-client.test.ts:109-110`・`126` と `test/helpers/stub-fetch.ts:22` にも「§7.3 は `"AbortError（タイムアウト）"` と表記するが」「設計書表記の旧称」という但し書きが残っている。振る舞い（`TimeoutError` を `DOMException` として投げる・リトライ対象にする）は既に実測に合っているので、作業は表記と但し書きの整理が中心になる。
