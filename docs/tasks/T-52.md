## 内容

D-02 §10 **Task J（ワークフローの実測確認）**。「状態」セルは「**未着手**（§8.1 (xvi)）。**自動検証を持たない確認専用のタスク**（§8 #66・#70）」。成果物は「使い捨てのワークフロー 1 本（§7 冒頭 (d) が定める形。確認後に取り除くので恒久的な成果物は無い）」。

§5.6 のワークフロー（`collect.yml`）は `jq` の型ガード・フォールバック・ステップの `if` 条件・新設ジョブのいずれも自動検証を持たない。`workflow_dispatch` はブランチで走らせても `reject-non-main`（§8 #35）が即座に失敗させるため、**`main` にマージするまで 1 回も実行できない**。シェルスクリプトへ切り出して `vitest` から検証する案は新しい carve-out を要するので採らない（§8 #66）。したがって本タスクは**コードの変更を伴わない目視確認**で、マージ後にしか実施できない。

§8.1 (xvi) の本文：「**使い捨てのワークフロー（`timeout-minutes: 1` + `sleep 120` + `$GITHUB_OUTPUT` へ 1 行書くステップ + `if: ${{ !cancelled() }}` のステップ + 同条件の検知ジョブ）を main で 1 回だけ走らせ、§7 冒頭の目視確認 (d) の 5 点を §10 Task J の完了報告に貼る**（#70。この項目が Task J の本体である）。**④⑤ は §7 冒頭 (d) が定める測定条件（④ は出力を書くステップを `sleep` の前に置き、ジョブに `outputs:` マッピングを宣言する／⑤ は `if: ${{ !cancelled() }}` のステップを `sleep` の後に置く）を満たした実行でのみ判断する**（満たさない実行の結果は偽陰性なので、正しい記述を撤回させてはならない）。確認できなかった場合は #70 の代替（①なら `if` を広げる／②なら「メールで届く」の記述を撤回する／④なら `published` の値域に空文字を加える／⑤なら「キャンセルでスキップされる」の記述を直す）に切り替え、§5.6・§6・§8 #64 の文言を同時に直す」。

**T-48（§8.1 (i)・(xi)〜(xv) を含む `collect.yml` の書き換え）が main にマージされた後でなければ実施できない**ので `depends_on: [T-48]`。

## 完了条件

実施者は本タスクの dev。**ただし ③（既定の失敗通知メールの受信）は dev ではなく開発者が確認する**：dev は `gh run view` で**実行全体の結論が `failure` であること**（②）までを確認し、③ は「開発者に確認を依頼し、回答を完了報告に転記する」。

- [ ] (1) **main へマージした直後の 1 回目の `collect` 実行**で §7 冒頭 (a)〜(c) を確認する
  - [ ] (a) 5 つの出力が `unknown` / 空文字でないこと
  - [ ] (b) ステップサマリに「収集 N 件 …」の 1 行が出ていること
  - [ ] (c) `deploy-pages` ジョブが走り、その中の `actions/checkout`（`ref: main`）→ `Pages 用にアップロード` → `deploy` の 3 ステップが成功していること（§8 #67）
- [ ] (2) 使い捨てのワークフローを main で 1 回だけ走らせて §7 冒頭 (d) の ①〜⑤ を（同節が定める測定条件を満たした実行で）確認する。このワークフローは **`on: workflow_dispatch` のみのファイル**として **PR で main にマージ → `gh workflow run` で 1 回実行 → 別 PR で削除**する（どちらのマージも開発者が行う）
  - [ ] ① `detect-collect-timeout` 相当ジョブが**起動する**（＝ジョブ単位の timeout で `cancelled()` が偽のまま `needs.*.result == 'cancelled'` になる）
  - [ ] ② 実行全体の結論が `failure` になる（dev が `gh run view` で確認する）
  - [ ] ③ 失敗通知メールが届く（**開発者が確認し、dev はその回答を完了報告に転記する**）
  - [ ] ④ **キャンセルされたジョブの `outputs` が後続ジョブへ引き渡されるか**（`$GITHUB_OUTPUT` へ書いた後にキャンセルされたジョブの出力を `needs.*.outputs` で読めるか。引き渡されない場合は空文字として扱う）。**測定条件：`$GITHUB_OUTPUT` へ書くステップを `sleep 120` の前に置き、かつ collect 相当ジョブに `outputs:` マッピングを宣言して検知ジョブで `needs.*.outputs` を `echo` する**（宣言が無いと `needs.*.outputs` は必ず空文字になり、引き渡しの有無と区別できない）
  - [ ] ⑤ **timeout したジョブ側で `if: ${{ !cancelled() }}` を付けたステップがスキップされること**（＝in-job では `cancelled()` が真になる）。**測定条件：`if: ${{ !cancelled() }}` のステップを `sleep 120` の後に置く**（前に置くとキャンセル前に完了して `success` になり測定にならない）
- [ ] (3) (a)〜(d) の結果を**本タスクの完了報告に貼る**（マージ後にしか実施できないため PR の説明には貼れない）
- [ ] (4) 外れた前提があれば §8 #70 の代替へ切り替え、§5.6・§6・§8 #64 の文言を同時に直す（①なら `if` を広げる／②なら「メールで届く」の記述を撤回する／④なら `published` の値域に空文字を加える／⑤なら「キャンセルでスキップされる」の記述を直す）。**設計書の文言を直す場合は `/design-doc reopen D-02` が先**
- [ ] **(e) は本タスクでは確認せず、以降のワークフロー変更 PR のレビュー項目とする**（§8 #71。`$GITHUB_OUTPUT` へ書く 5 本の値が数値・真偽値・固定語彙だけであることを毎回繰り返して確認する）
- [ ] 使い捨てのワークフローが別 PR で削除され、リポジトリに恒久的な成果物が残っていない
- [ ] 本タスクは**自動検証を持たない確認専用のタスク**なので、新しい自動テストは追加しない（§8 #66）。collector 側のコードに変更が入る場合のみ品質ゲート（`npm run lint && npx tsc --noEmit && npx vitest run`）を通す
