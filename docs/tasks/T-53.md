### 開発者に確認してほしいこと

1. **D-04 §4.9 のコード片からの意図的な逸脱が 1 件ある。** import を `package:drift/remote.dart`（設計書の字面）ではなく `package:drift/isolate.dart' show DriftRemoteException` にした。`@experimental` は `remote.dart` の library 宣言に付き型自体には付かないため、注釈のない `isolate.dart` の再 export 経由なら `// ignore: experimental_member_use` を書かずに済む（`flutter analyze` は警告ゼロが必須）。設計書のとおりに書くと ignore が必要で、D-04 §4.9 には ignore の記述が無い。**どちらを採っても D-04 の改訂が必要**なため、lint 抑止を無くせる側を採った（FOLLOWUPS 2-16）
2. **`.github/workflows/app-ci.yml` の検査が §4.8 の抜粋から育っている。** 追加・変更はすべて「期待値を狭める／同等」で、§4.8 が禁じる緩和は入れていない（1 度入れた `--exclude='*.g.dart'` は第 3 周で撤回）。乖離の記録は FOLLOWUPS 2-13
3. **`releaseSafeError` の実効は現状ゼロである。** 既定の `DevelopmentFilter` が release の出力自体を落とすため（logger 2.8.0 で実測）。この変更は `ProductionFilter` 等に替えたときの防御で、設計書 §4.9・§8.2.4 の「release でも `Level.warning` は出力される」という前提は事実と異なる（FOLLOWUPS 2-17）
